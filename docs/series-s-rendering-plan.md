## 调色色带

用同一个 D3D12 命令列表、描述符、常量和视口重复绘制调色通道，直接回读 10 位渲染目标。发生色带时，进入调色的 FP16 图像仍有平滑渐变。手机近景的固定区域中，10 位输出仅有 96 种 RGB 值。改用显式三线性插值后，同一绘制的同一区域增至 4,980 种，纵向相邻像素的最大通道差达到 32 个码值的比例从 1.599% 降至 0.074%。该故障位于调色通道，早于最终的 8 位输出。

| 验证 | GPU 回读结果 |
| --- | --- |
| 显式切换为点采样 | 另一手机近景帧的同一区域由 7,862 种 RGB 降至 560 种。将 33³ 与 64³ 调色表的四处采样一并改为点采样后降至 330 种，复现大面积彩色色带。 |
| 重新创建原版 D3D12 管线 | 33 次同帧绘制与原管线的 RGB 输出一致。这次运行未出现原始故障。 |
| 独立纹理测试 | RTX 5060 Laptop 驱动 621.01 与 Microsoft WARP 对 64³ RGBA16F 纹理的 65,536 个位置均正确执行 0x14 线性过滤，10 位 RGB 与预期一致。 |

同一构建和相同内容的 64³ 调色表也能输出平滑渐变。游戏内间歇性出现点采样特征的具体触发条件仍待定位。两个像素着色器按 DXBC 摘要匹配，对三处 33³ 采样和一处 64³ 采样读取相邻 texel 并显式插值。两份 DXIL 均通过 Windows SDK 验证和 D3D12 管线创建。着色器缓存会随转译器版本自动更新。

本机诊断产物位于验证根目录。原始故障的同帧对照位于 `20261127-191949-color-paired-pso`，点采样对照位于 `20261127-204152-color-point-positive-control`。正常启动脚本实测记录位于 `20261127-205710-color-project-launch`，手机近景帧为 1657、1659、1661。

新构建约 67 秒进入高绘制量的 3D 场景，连续输出约 19 分钟，测试进程随后手动结束。日志中无设备丢失、驱动重置或内存分配失败。已核对人物近景、室内移动及门前画面，实走到室外和下一检查点待验收。日志按时间段汇总的平均帧时间中位数为 682 ms，P95 为 1,277 ms。

## XCL 对照

XCL 将 Xbox 的一个 Wave64 映射到同一线程组的两个硬件 Wave32。计算、网格与 ES+GS 着色器用组共享内存同步两个半波的掩码和跨 lane 读写。顶点与像素着色器无此组共享通路，XCL 另行跟踪可静态还原的高半波值，部分 Wave 的规约仍有限制。 [XCL PR #67](https://github.com/xcl-dev/xcl/pull/67) · [Wave64 on Wave32 设计](https://github.com/xcl-dev/xcl/blob/main/docs/wave64-on-wave32.md)

cool_fox 的 `VICTORY_WAVE64_PAIRED=1` 在 Wave32 宿主上尝试为部分 Wave64 计算着色器生成配对执行路径。当前实现让每个宿主 lane 处理两个客体 lane，接收线程数为完整 Wave64 整数倍的计算组。已有记录中 6 个筛选测试通过，其中 3 个有 GPU 回读，覆盖跨半波读、规约、共享内存和分支掩码。

基线拒绝的 5 个着色器在 `paired-first-pso.txt` 的独立测试中均通过 DXIL 验证和 D3D12 PSO 创建。最新运行日志确认了其中 3 个的宿主管线，`6b82bc7d22016cb5` 和 `926c46bab3b86bd6` 的实战调度及输出待核实。5 个样本也在 XCL 中生成了 HLSL，其中 3 个留有 DXC 编译产物。下一步在两个后端分别建立对应资源绑定，用相同输入比较 GPU 回读。 [cool_fox 配对实现](../cool_fox/crates/victory-shader/src/emit/bitcode/paired.rs)

XCL 以独立程序作为对照，cool_fox 在现有编译器中实现并测试所需语义。XCL 标注 GPL-2.0-only，cool_fox 标注 GPL-3.0-or-later。 [XCL 许可证声明](https://github.com/xcl-dev/xcl/blob/main/Cargo.toml) · [项目许可证说明](../LICENSE-NOTICES.md) · [GNU GPL 版本兼容性](https://www.gnu.org/licenses/gpl-faq.html#v2v3Compatibility)

## 本轮目标和验收

范围为序章和紧随其后的第一个可达检查点。在同一台机器固定存档、Series S 配置、960 × 540 窗口上限和输入路线，使用下列 5 个检查点。全数应持续输出对应的 3D 场景，至少 4 个通过画面比对。

| 检查点 | 画面比对 |
| --- | --- |
| 序章开场人物近景 | 脸、眼睛、头发和衣物几何与材质正常，连续帧无黑块或部件消失。 |
| 室内转动视角并移动 | 墙面、地面、道具和灯光随视角持续更新，主要表面无黑块、明显闪烁或明显错位。 |
| 门口室内外过渡 | 门框和玻璃边缘稳定，逆光、雾和透明部件无明显破碎或持续泛白。 |
| 实际走到室外并转动视角 | 近景人物、远景建筑和阴影连续出现，移出再移入视野后主要贴图与几何仍可见。 |
| 进入下一可达检查点 | 场景切换后持续有 3D 画面，关键人物与场景连续更新。 |

画面按同一场景、机位和动作的连续帧判断。能取得 Series S 原生参考时以其校验光照和材质，只有本地参考的检查点记录为本地回归对照。沿固定路线实测 10 分钟，记录设备丢失、驱动重置、显存分配失败和进程退出，验收要求这些故障均为零。当前性能基线约 1–2 FPS，记录帧时间中位数和 P95。

## 执行顺序

1. **先复现冷启动长黑屏。** 以首次可辨认的 3D 帧为终点，分别做两次着色器及 PSO 冷缓存、两次暖缓存的测试，每组保留同样的镜像缓存和存档。记录启动、首个高绘制帧、关键 PSO 就绪、关键贴图上传及首个可见 3D 帧的时间。拟定验收线为冷缓存 ≤180 秒，暖缓存 ≤120 秒。
2. **验证 Wave64 计算输出。** 对 5 个样本依次确认 DXIL、PSO、实际调度和输出，优先核实日志里缺少记录的两个着色器。用合成输入检查跨半波读、EXEC 掩码、分支、共享内存和不完整线程组的处理。以 XCL 的 GPU 回读或可计算的期望值核对输出，记录失败对应的 shader hash 和渲染通道。
3. **按渲染通道定位剩余缺陷。** 先查脸部近景和主要几何，逐帧关联跳过的绘制或管线、深度缓冲、材质描述符及纹理是否已上传。再独立开关 BVH 构建与纹理同步路径，分别比较室内阴影、门口雾和透明材质。只有日志和画面共同指向 Wave64 时，才扩大到对应的网格或顶点、像素着色器。
4. **跑完固定路线。** 用通过前几项的构建复测全部 5 个检查点。每次记录构建哈希、实际生效的开关、缓存初始状态、输入与帧号，以及显存峰值和关键管线失败。以实拍连续帧作为画面验收证据。
